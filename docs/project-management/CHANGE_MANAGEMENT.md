# Change Management

1. Open an issue or discussion for significant architecture, scope, or release changes. Describe the affected users, components, and reason for the change.
2. Record the project owner's decision in the issue or pull request. Include compatibility, migration, and recovery implications where applicable.
3. Keep implementation pull requests focused. Record the validation performed and any checks that could not be run.
4. Update the affected documentation when behavior changes. Capture user-visible changes in the [changelog](../../CHANGELOG.md) and update the [repository roadmap](../../ROADMAP.md) or [Risk Register](RISK_REGISTER.md) when priorities or risks change.

Apply the existing [contribution guidance](../../CONTRIBUTING.md) and [security reporting policy](../../SECURITY.md).
